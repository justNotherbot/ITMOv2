# FEATURES (practice_04)

Ниже описаны две атомарные, проверяемые фичи для проекта practice_04. Каждая фича имеет чёткие критерии приёмки и предполагает покрытие e2e-тестами с использованием скилла webapp-testing.

## Feature A — MathJax 3: базовая интеграция и рендеринг формул

- Цель: подключить MathJax 3 и обеспечить корректный рендер LaTeX-формул во всех страницах, где встречаются формулы, с поддержкой inline и block режимов.

- Объём работ:
  - Добавить скрипт MathJax 3 (UMD) и конфигурацию с делимитерами: inline — `$...$` и `\(...\)`, display — `$$...$$` и `\[...\]`.
  - Включить скрипт и конфигурацию в общий шаблон (layout), чтобы они загружались на всех контентных страницах.
  - На странице «Ряды Фурье» разместить как минимум по одному примеру inline и block формул (например, inline: `$f(x)=\\sum_{n=1}^{\\infty} a_n\\cos(nx)+b_n\\sin(nx)$`; block: `$$S_N(x)=\\sum_{n=1}^{N}\\big(a_n\\cos(nx)+b_n\\sin(nx)\\big)$$`).
  - Обеспечить повторный вызов `MathJax.typesetPromise()` при динамической вставке формул (если таковые присутствуют на странице «Демонстрации»).

- Критерии приёмки:
  - На страницах «Ряды Фурье», «Полиномы Чебышева» и «Теория приближения» присутствует тег скрипта MathJax и корректная конфигурация делимитеров.
  - На странице «Ряды Фурье» inline-формула и block-формула отрисованы элементами `mjx-container` (MathJax v3 HTML-вывод), а исходный TeX не виден в DOM как обычный текст.
  - Скрипт подключается один раз и не дублируется на странице.

- Тестирование (e2e, webapp-testing):
  - Запуск сервера и переход на `/fourier`.
  - Проверка наличия тега `<script>` для MathJax (по `src` содержит `mathjax`).
  - Проверка наличия как минимум двух `mjx-container` на странице: один для inline, один для block.
  - Проверка, что строковые делимитеры `$...$`/`$$...$$` не остаются в тексте видимыми пользователю.

- Вне объёма: расширенная настройка шрифтов/вывода SVG, динамическая загрузка только на отдельных страницах.


## Feature B — Интерактив «Частичные суммы ряда Фурье» (square wave)

- Цель: добавить на страницу «Ряды Фурье» минимальный интерактив: слайдер порядка частичной суммы N для квадратного сигнала с отрисовкой кривой. Обновление графика при изменении N выполняется на стороне клиента (без серверного API).

- Объём работ:
  - В секции «Демонстрации» страницы «Ряды Фурье» добавить контрол `input[type="range"]` с параметрами: min=1, max=50, step=1, value=10. Добавить `aria-label="Порядок частичной суммы"` и `data-testid="fourier-slider"`.
  - Отображать текущий N в элементе `span` с `data-testid="fourier-N-label"`, формат: `N = <значение>`.
  - Добавить SVG-график с одним путём кривой для аппроксимации квадратного сигнала частичной суммой ряда Фурье. Главный путь имеет `data-testid="fourier-plot"`.
  - При изменении слайдера пересчитывать значения ряда на клиенте и обновлять атрибут `d` у пути графика; триггерить повторный рендер.

- Критерии приёмки:
  - На странице `/fourier` присутствуют: слайдер, подпись текущего N, SVG-график с путём.
  - Значение на `span[data-testid="fourier-N-label"]` соответствует значению слайдера.
  - При изменении слайдера (например, с 10 на 15) атрибут `d` у `path[data-testid="fourier-plot"]` изменяется, что свидетельствует об обновлении кривой.
  - Элементы управления имеют корректные aria-атрибуты для доступности.

- Тестирование (e2e, webapp-testing):
  - Запуск сервера и переход на `/fourier`.
  - Проверка наличия `input[data-testid="fourier-slider"]`, `span[data-testid="fourier-N-label"]`, `path[data-testid="fourier-plot"]`.
  - Считывание начального `value` слайдера и текста метки N.
  - Взаимодействие: установить новое значение слайдера, проверить обновление метки N и изменение атрибута `d` у пути.

- Вне объёма: серверный API для вычислений, выбор разных сигналов, антиалиасинг/сглаживание, отображение спектра коэффициентов — это будут отдельные фичи.
