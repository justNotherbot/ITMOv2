## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: определить критические дефекты в изменениях `TRAINING_PR.diff` и оформить их в формате «candidate → evidence → check».
- Роль AI: строгий код-ревьюер, опирающийся только на diff и правила из `context.md`; фиксирует только подтверждённые дефекты.

### 2. Входы и источники

- Обязательный вход: содержимое `TRAINING_PR.diff`.
- Разрешённые файлы и источники: `TRAINING_PR.diff`, `context.md`, `problem.md`, `prompts.md`; официальная документация Python и уже используемых библиотек.
- Context Pack — факты, правила, примеры и ограничения: см. `context.md` (версии Python, ограничения зависимостей, формат входа/выхода API, плохие/хорошие примеры, запреты).

### 3. Задача и артефакты

- Что сделать: извлечь из diff критические дефекты; для каждого дать ссылку на файл/строку (evidence) и воспроизводимую проверку (check); обновить журнал в `prompts.md`.
- Что вернуть: список дефектов в формате «candidate → evidence → check»; ссылки на строки diff; короткие команды/шаги для проверки.

### 4. Формат результата

- Структура ответа: маркированный список дефектов; на каждый — три подпункта (candidate, evidence с ссылками на строки, check с шагами проверки).
- Ограничения объёма: только критические дефекты; без повторов; без необоснованных рассуждений.

### 5. Полномочия и запреты

- Разрешено: читать указанные файлы; ссылаться на строки diff; предлагать проверки через curl/моки.
- Запрещено: вносить изменения в код; добавлять зависимости; использовать предположения без ссылок; выходить за рамки файлов.

### 6. Рабочий процесс и остановка

- Шаги: проанализировать diff → составить кандидаты → подтвердить evidence со ссылками → сформировать проверки → отфильтровать пункты без evidence.
- Когда остановиться и запросить человека: если требуется контекст вне diff или политики безопасности не определены в `context.md`.

### 7. Проверки и evidence

- Как проверять утверждения: HTTP-запросы к эндпоинту, симуляция исключений LLM заглушкой, проверка кодов ответов и поведения на больших payload.
- Какое evidence сохранить: ссылки на файлы и номера строк из `TRAINING_PR.diff`, ожидаемые коды ответов и симптомы.

### 8. Definition of Done

- Задача закончена, когда: у каждого дефекта есть evidence и воспроизводимая проверка; журнал `prompts.md` обновлён; соблюдены ограничения из `context.md`.

## Сравнение двух запусков

| Проверка | Zero-shot | С master prompt | Вывод команды |
|---|---|---|---|
| Есть ссылка на файл или строку | Да | Не запускалось | В zero-shot добавлены ссылки на файлы/строки в `problem.md` |
| Вывод подтверждён diff или правилом | Да | Не запускалось | Все пункты подкреплены ссылками и правилами из `context.md` |
| Соблюдены границы AI | Да | Не запускалось | Соблюдены ограничения по файлам и зависимостям |
| Есть воспроизводимая проверка | Да | Не запускалось | Для каждого дефекта есть шаги проверки |
