01 / Method

How was SpecKit used?
As a spec-driven development framework for an LLM: define intent, research decisions, design contracts, generate executable tasks, implement incrementally, and verify each result.

SPECIFY

Intent before code

User stories, functional requirements, edge cases, measurable success criteria.

PLAN → TASKS

Design as a map

Technical context, constitution gates, data model, API contracts, quickstart, then file-level tasks.

IMPLEMENT → VERIFY

Evidence at every step

Focused tests, browser smoke checks, latency checks, and traceable task status instead of “it seems to work.”

02 / SpecKit vs OpenSpec

Both make LLM work more deliberate. They differ mainly in how much process and artifact structure they impose.

DimensionSpecKitOpenSpec
Core ideaStructured spec-driven delivery: specification → plan → tasks → implementation.Lightweight, change-oriented specifications designed to guide an agent through a focused change.
ArtifactsExplicit feature spec, research, plan, model, contracts, quickstart, tasks.Usually a smaller proposal/change specification with less ceremony.
Best fitMulti-layer work where traceability, gates, dependencies, and acceptance evidence matter.Fast iteration, smaller changes, or teams that want a compact specification loop.
This projectUsed. The project needed UI, Logic, and Common Contract alignment.Useful alternative, but not the workflow used for this implementation.

04 / The common contract

Why? Because a graph, a label, an accessible description, and a server response must describe the same mathematical state. Without a shared vocabulary, each layer can be locally correct and globally contradictory.

PAGE

Page identity

Route, topic, title, heading, canonical path, sections, breadcrumbs, and navigation for all six destinations.

DEMO STATE

One committed state

demo_id, normalized parameters, status, time/frame, calculation mode, and structured error. Visual and accessible projections come from the same object.

MATH API

Stable meaning

v1, operation, normalized input, ordered finite output, domain, tolerance, duration, and cache status.

ERROR + FALLBACK

Graceful degradation is part of the feature

Validation errors identify the field and constraint. The last valid demo state is preserved. If JavaScript, SVG, MathJax, or a service is unavailable, the learner still gets a plain-language mathematical explanation.
