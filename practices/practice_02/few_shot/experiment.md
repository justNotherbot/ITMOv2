- Что хотим улучшить: заменить неполноценные формулировки нагрузки («5 RPS, 10 мин»), метрик («Время ответа, ошибки») и порогов («P95 < 1 с» без обоснования) на конкретизированные: разделение `llm:` / `gateway:` / `duration:`, имена метрик с единицами (миллисекунды, %, RPS, коды) и обоснование допустимого предела через характер распределения (нормальное / детерминированное / равномерное с отсечкой), чтобы сделать проверки воспроизводимыми.

## Примеры

### Хороший результат

Пример строки, которую считаем эталоном (даём модели как positive few-shot):

```markdown
| P95 при 256 КБ diff | gateway: 5 RPS на POST `/api/reviews` diff≈256 КБ (≈64k символов) llm: 5 tokens/sec (мок 300 мс) duration: 10 мин steady-state | P95 response_latency < 1000 мс — так как задержка при мок-LLM подчиняется нормальному распределению около 600±150 мс, хвост >1 с указывает на очередь gateway | Задержка ответа (response_latency / http_request_duration_ms, миллисекунды, гистограмма) ; Доля ошибок (http_error_rate, %, по кодам 4xx/5xx) | k6 summary + Grafana APM p95 панель |
```

```markdown
| Лимит размера | gateway: 1 RPS diff 30k символов (~300 КБ) llm: 0 tokens/sec (отсечка до LLM) duration: 2 мин (120 проб) | 100% 413 за ≤500 мс — так как проверка синхронная на gateway и подчиняется детерминированному распределению <100 мс | Код ответа (http_response_code, код 413) — доля 413 (%); Задержка отклонения (rejection_latency_ms, миллисекунды) | Access-лог gateway histogram |
```

Признаки хорошего: `llm:` + `gateway:` + `duration:` явно разделены, метрика имеет имя + единицу, порог с «— так как ... распределение ...», evidence — конкретный инструмент/панель.

### Плохой результат

Негативные примеры (negative few-shot, то как было до улучшения — просим LLM так НЕ делать):

```markdown
| P95 при 256 КБ diff | 5 RPS, 10 мин, diff≈256 КБ | P95 < 1 с | Время ответа, ошибки | Метрики APM/клиента |
| Лимит размера | 1 RPS, отправка 25k+ символов | 100% 413 | Код ответа | Логи HTTP |
| Стабильность таймаута LLM | 1 RPS, инъекция задержки 12 с | 100% 503/504 за ≤11 с | Доля 5xx по типам | Логи и трассы |
```

Проблемы плохого: нагрузка свалена в одну фразу без разделения gateway/llm/duration, «Время ответа, ошибки» — без имени метрики и единицы, «P95 < 1 с» без обоснования распределения, evidence — общие слова без конкретного histogram/панели.
